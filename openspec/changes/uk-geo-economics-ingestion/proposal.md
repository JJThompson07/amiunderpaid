## Why

Per-occupation regional pay data for the UK doesn't exist in this system. Confirmed against live data on 2026-11-10:

- UK `regional_salary_benchmarks` holds 782 records. All of them are ASHE Table 7.7a all-roles aggregates (`title: 'All'`, `id_code` = the location's GSS code), so a lookup by SOC returns nothing.
- So every UK result shows "National". The "micro" tier of the MCA score always uses the national figure scaled by a regional modifier, and that modifier was itself broken until `server-side-mca-engine`.

The BenchmarkMyRole API's value proposition is "pay for this role, in this place, in context". That needs three things:

1. Real occupation × region pay data.
2. A way to turn a user's location (place name or postcode) into the geography that data is published at.
3. The cost-of-living context buyers expect next to a salary figure: inflation and rents.

All of it is Open Government Licence data, so the API can stand on it alone while the Reed licence question is open.

Source checks (2026-11-11):

- **ASHE Table 15 (2026 provisional), "Work Region Occupation SOC20", Full-Time sheet:**
  - The zip contains both 4-digit and 3-digit SOC workbooks.
  - Rows are `"<Region>, <Occupation>"` with a `'2134`-style code. Coverage is 11 GB regions; Northern Ireland isn't included.
  - At 4-digit SOC the median is published for 1,409 of 4,532 cells (31%) and the mean for 3,247 (72%), with no percentiles at all. At 3-digit SOC the median is published for 820 of 1,144 cells (72%) and p25 for 653.
  - So a single lookup can't serve most requests; a cascade is required.
- **CPIH:** the ONS timeseries `L522/MM23` JSON is machine-readable.
- **Private rents:** the ONS Price Index of Private Rents is published as a dated xlsx. The current file's link has to be discovered from the dataset page.

## What Changes

- **New seeder scope** "UK regional by occupation (ASHE Table 15)" in the admin seeder:
  - Parses workbook 15.7a (4-digit and 3-digit) into `regional_salary_benchmarks` records with `id_code` = SOC code, `location` = region, `geo_code` = region GSS code and `soc_level: 4 | 3`.
  - Writes to Firestore only. The engine is the only reader, which keeps Algolia's regional record count unchanged.
- **New static geography lookup** `shared/data/uk-geo.json`, generated by a committed script from ONS Geoportal and ONS Postcode Directory lookups:
  - Maps every `ONS_LOCATIONS` entry to its GSS code, upper-tier area and region.
  - Maps every postcode outcode to its majority local authority and region.
  - `shared/utils/ukGeo.ts` exposes `resolveUkLocation(input)` → `{ name, gss, level, regionGss, regionName } | null`.
- **Engine: UK regional micro cascade** in `server/utils/engine/baselines.ts`, for the user's region:
  1. SOC 4-digit median.
  2. Otherwise the SOC 4-digit mean scaled by that occupation's national median/mean ratio.
  3. Otherwise the parent SOC 3-digit median scaled by the national SOC4/SOC3 ratio.
  4. Otherwise none, falling back to the existing national × modifier path.

  Each result carries a `basis` field naming which step produced it.

- **New monthly cron** `GET /api/cron/sync-economics` (Vercel cron, `CRON_SECRET`-guarded like the existing crons):
  - Ingests CPIH into `uk_economic_indicators/cpih` and the latest private-rents release into `uk_rents/{gss}`.
  - Each source updates independently, keeping the last good value on failure.
- **New server utility** `getGeoEconomics(location)` returns region, CPIH (latest + 12-month change), and median rent for the area (or its parent area, falling back to the region). It's consumed by `api-keys-metering-billing` (`/v1/geo`) and `amiunderpaid-seo-funnel`.
- **Admin:** the admin actions page shows each economics source's last successful sync and last error.

## Scope

- Table 15 parsing, seeding, and the engine's regional cascade.
- The location lookup data, its generator script and its resolver.
- CPIH and rent ingestion with monthly refresh.
- The geo-economics read utility.

## Non-goals

- **Map boundaries.** The planning decision was to replace `public/uk-regions.json`'s 2018 boundaries, but that file is consumed only by the recruiter territory map today. It moves to `recruiter-deprecation-and-regional-explorer`, together with the explorer that will use it.
- **UK House Price Index:** `amiunderpaid-seo-funnel`.
- **Northern Ireland occupation × region data.** Table 15 doesn't publish it, so NI keeps the national × modifier path and the API reports `basis: 'national'`.
- **Automating the annual ASHE download.** It stays a manual admin upload, as today.
- **USA geo-economics.** The API is UK-only at launch.

## Capabilities

### New Capabilities

- `uk-geo-economics`: the location resolution data and resolver, CPIH and rent ingestion, its refresh cadence and failure behaviour, and `getGeoEconomics`.

### Modified Capabilities

- `government-data-seeder`: adds the Table 15 scope (Firestore-only, SOC level recorded).
- `benchmark-engine` (introduced by `server-side-mca-engine`): UK regional micro data uses the Table 15 cascade with a reported `basis`.
