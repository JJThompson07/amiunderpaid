## Why

The recruiter territory product is being replaced by the BenchmarkMyRole API (decided 2026-11-10). It has no paying customers. Production Firestore on 2026-11-10 had `territory_category_owners` 0, `leads` 0 and 3 users with the recruiter role; Stripe test mode had 5 test subscriptions, and live mode is still to be checked. It's still the largest surface in the codebase:

- 7 pages, 5 territory components, 8 composables
- 11 server routes, 2 server utilities, 2 Stripe flows
- 5 e2e suites
- a recruiter grid and lead modal on every UK/US results and jobs page

`site-separation` deliberately left it running on `www.benchmarkmyrole.com` until this change.

One part of it is worth keeping: the ECharts UK map in `app/components/Territory/Map.vue`. With Table 15 data (`uk-geo-economics-ingestion`), a public map of "what this role pays across the UK" is a strong consumer and SEO page for amiunderpaid, and a shop window for the API. The map's boundary file `public/uk-regions.json` is from 2018 (`ctyua18cd`): it still has Cumbria, Northamptonshire and separate Bournemouth/Poole, and is missing Cumberland and Westmorland and Furness. It needs replacing before it's reused.

## What Changes

- **Removed: the recruiter portal and territory product.**
  - Pages: `app/pages/recruiter/**`, `app/pages/admin/{recruiters,banding}.vue`, `app/layouts/loginLayout.vue`.
  - Components: `app/components/Territory/**`, `Modal/{CancelTerritory,RequestAccess}.vue`, `Toast/NationalConfirmation.vue`, `AmI/{RecruiterButton,LeadFloatingButton}.vue`, `AmI/Card/LeadContact.vue`.
  - Composables: `use{RecruiterCards,Territories,TerritoryClaims,ScheduleMath,Pricing,ContactSettings}`.
  - Middleware: `recruiters`, `recruiter-verified`.
  - Server: `server/api/admin/recruiters/**`, `server/api/user/{leads,recruiter}/**`, `server/api/user/search/recruiter-card.get.ts`, `server/api/stripe/{create-checkout,cancel-territory}.post.ts`, the territory branches of `webhook.post.ts`, `server/utils/{territoryFulfillment,billingAlerts}.ts`, `scripts/migrate-territory-claims.ts`, `utils/bands/**`, `RECRUITER_TERRITORIES_*`.
  - Matching tests and e2e suites, and the recruiter i18n (`recruiter.json` plus recruiter keys elsewhere).
- **Removed from results pages:** the "Take action" recruiter grid and lead modal on `/salary` and `/jobs`, and `useAffiliateOfferToast`'s `hasRecruiters` gate. Affiliate offers already cover that slot.
- **Renamed:** `useRecruiterAuth` → `useAuth`. It's the generic Firebase auth used by forgot-password, email verification and (after `api-keys-metering-billing`) the developer portal. Logout now goes to the current site's home. `useUserRole` drops `isRecruiter`.
- **Data, stop reading only:**
  - Code stops reading `territory_category_owners`, `leads` and `recruiter_contact_settings`, and the recruiter fields on `users`.
  - Their Firestore rules become deny-all (server-only).
  - **No data is deleted.** Export and deletion is a separate later change after a 30-day burn-in (CODE_STANDARDS §10).
- **Routing** (in `shared/utils/hostRouting.ts`):
  - `/recruiter/territories/**` on any host → 301 `https://www.amiunderpaid.co.uk/explorer`.
  - Every other `/recruiter/**` → 301 `https://www.benchmarkmyrole.com/dashboard`.
  - The `www.benchmarkmyrole.com` temporary allowlist narrows: `/recruiter/**` goes; `/api/**` becomes `/api/developer/**` plus `/api/stripe/webhook`; `/auth/**` stays only if Firebase's action URL points there (pre-flight).
  - `/explorer` on `.com` → 301 `.co.uk/explorer` (UK-only data).
- **New: the regional explorer** at `www.amiunderpaid.co.uk/explorer`.
  - A public UK choropleth: pick a role (job autocomplete → SOC) to see its pay by GB region, with each region's `basis` labelled; with no role selected, it shows all-roles median pay by county/unitary authority.
  - Beside the map, a panel shows the sample `/v1/benchmark` JSON for the current selection, with a "Try it live" link to the benchmarkmyrole playground.
  - Fully i18n'd, ISR-cacheable, listed in the `.co.uk` sitemap.
- **New boundaries:** current ONS region and county/unitary authority boundaries (generalised), generated by a committed script into `public/geo/`. `public/uk-regions.json` is deleted.
- **New endpoint** `GET /api/explorer/regions?soc=`: per-region values with `basis`, or all-roles values per area when `soc` is absent, from the engine's baseline reads.

## Scope

- Removing everything above, plus the routing updates.
- The explorer page, its map component, endpoint and boundary data.

## Non-goals

- **Deleting recruiter data** (Firestore documents, Stripe customers and products, recruiter Firebase Auth users). That's a separate change after the burn-in.
- **Removing `app/plugins/tenant.ts`.** Its remaining consumers (`app.vue` theme, analytics `brand`) work correctly on non-ISR routes and are covered by the host rule from `site-separation`.
- Legal text. `terms-and-conditions.json` mentions recruiters in 10 places; rewording it is the user's call (task 1.5). This change doesn't edit legal copy unilaterally.
- Sub-regional occupation data (not published by ONS).

## Capabilities

### New Capabilities

- `regional-explorer`: the explorer page, endpoint, map behaviour, basis labelling and API sample panel.

### Modified Capabilities

- `site-host-routing`: recruiter redirects, the narrowed benchmarkmyrole allowlist, and the UK-only explorer.
- `affiliate-offers`: the toast is no longer suppressed by recruiter presence.

### Removed Capabilities (requirements removed by delta)

- `stripe-checkout-security`: territory checkout requirements removed; webhook dedup is kept (it's used by the API billing branch).
- `rate-limiting`: the leads and request-access route examples are replaced.
